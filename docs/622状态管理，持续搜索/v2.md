## 二、修正后的状态机设计

### 2.1 状态转移表（完整版，含所有边界条件）

```
★ 最高优先级规则：EMERGENCY 事件在 transition() 最前面判断，短路返回

┌────────────┬──────────────────┬──────────────────────┬──────────────┬─────────────────────────┐
│ 当前状态    │ 事件              │ 守卫条件              │ 目标状态      │ 动作                     │
├────────────┼──────────────────┼──────────────────────┼──────────────┼─────────────────────────┤
│ *任意*      │ EMERGENCY         │ —                    │ EMERGENCY_RTL│ pub /uav/state_cmd RTL   │
│ IDLE       │ START_MISSION     │ —                    │ SEARCHING    │ 初始化搜索航点            │
│ SEARCHING  │ TARGET_DETECTED   │ conf >= θ₂(0.7)      │ APPROACHING  │ 直接逼近                 │
│ SEARCHING  │ TARGET_DETECTED   │ θ₁(0.6)<=conf<θ₂     │ VERIFYING    │ 启动多次确认             │
│ SEARCHING  │ TARGET_DETECTED   │ conf < θ₁            │ SEARCHING    │ 忽略，继续搜索            │
│ SEARCHING  │ SEARCH_EXHAUSTED  │ 轮次 > MAX_ROUNDS(3) │ IDLE         │ 发布任务失败             │
│ VERIFYING  │ VERIFY_RESULT     │ 收满K次 且 均值>=θ₂   │ APPROACHING  │ 融合位置                 │
│ VERIFYING  │ VERIFY_RESULT     │ 收满K次 且 均值<θ₂    │ SEARCHING    │ 重置搜索                 │
│ VERIFYING  │ VERIFY_FAIL       │ fail_count >= K      │ SEARCHING    │ VLM连续失败，重置         │
│ VERIFYING  │ VERIFY_TIMEOUT    │ 进入状态超过15s无结果  │ SEARCHING    │ 超时回退                 │
│ APPROACHING│ TARGET_REACHED    │ dist < d_thresh(2m)  │ COMPLETED    │ 最终确认                 │
│ APPROACHING│ TARGET_UPDATED    │ —                    │ APPROACHING  │ 更新位置, miss_count=0   │
│ APPROACHING│ TARGET_LOST       │ miss < MAX_MISS(5)   │ APPROACHING  │ miss_count++             │
│ APPROACHING│ TARGET_LOST       │ miss >= MAX_MISS     │ SEARCHING    │ 以最后位置螺旋搜索        │
│ COMPLETED  │ —                 │ 终态                  │ —           │ 悬停                     │
│ EMERGENCY  │ —                 │ 终态                  │ —           │ RTL                      │
└────────────┴──────────────────┴──────────────────────┴──────────────┴─────────────────────────┘
```

### 2.2 关键修正点

1. **消除 DETECTED 瞬态**：原来的 DETECTED 状态在同一调用栈内立即转走，实际不存在独立 tick。修正为直接从 SEARCHING 根据 confidence 分发到 VERIFYING 或 APPROACHING。

2. **EMERGENCY 短路**：`transition()` 开头先判断 EMERGENCY，避免先触发其他转移再覆盖。

3. **VERIFYING 增加超时和失败处理**：在 `_tick()` 中检查进入 VERIFYING 的时间，超过 15s 无结果则回退；VLM 返回 None 时计为 fail。

4. **SEARCHING 增加轮次上限**：`search_round` 计数器，航点遍历完一轮 +1，超过 MAX_ROUNDS 则任务失败。

## 四、VLM 调用策略修正

### 4.1 防止请求堆积（核心修正）

```python
# mission_manager_node.py 中增加
self._detection_in_flight = False

def _request_detection(self):
    if self._detection_in_flight:
        return  # 上一次请求还没返回，跳过
    self._detection_in_flight = True
    self.last_vlm_time = rospy.get_time()
    msg = String()
    msg.data = json.dumps({"target": {"text": self.fsm.target_text}})
    self.detection_req_pub.publish(msg)

def _on_detection(self, msg):
    self._detection_in_flight = False  # 无论成功失败都清除
    # ... 处理结果 ...
```

### 4.2 异步检测（沿用现有线程模式）

detector_node.py 现有的 `_cb_instruction` 已用 `threading.Thread(daemon=True)` 执行检测。改造时**必须沿用此模式**：

```python
def _on_detection_request(self, msg):
    if self._detecting:  # 并发保护
        return
    threading.Thread(target=self._run_detection_for_request,
                     args=(msg,), daemon=True).start()
```

### 4.3 双层 confidence 融合

现有 `detection.confidence` 实际是深度有效像素比例（`base_detector.py`），不是语义置信度。修正方案：

```python
# qwen_vl_grounding.py 中修改 _call_api，在 prompt 末尾加：
# "请同时输出你对检测结果的置信度(0-100)，格式: confidence: XX"
# 解析后作为 semantic_conf

# detect() 中融合：
final_confidence = 0.6 * semantic_conf + 0.4 * depth_conf
```

### 4.4 timeout 修正

将 `qwen_vl_grounding.py` 的 `self.timeout` 从 90s 降至 **20s**（实际 VLM grounding 通常 3-8s 返回），重试逻辑内聚在 detector_node 内部。

## 五、安全防护增强

### 5.1 地理围栏

```python
# mission_manager_node.py
GEO_FENCE = {"x": (-50, 50), "y": (-50, 50), "z": (1, 20)}

def _publish_target(self, pos):
    x = max(GEO_FENCE["x"][0], min(GEO_FENCE["x"][1], pos[0]))
    y = max(GEO_FENCE["y"][0], min(GEO_FENCE["y"][1], pos[1]))
    z = max(GEO_FENCE["z"][0], min(GEO_FENCE["z"][1], pos[2] if len(pos) > 2 else 8.0))
    if (x, y) != (pos[0], pos[1]):
        rospy.logwarn("[Mission] Target clipped by geofence")

    msg = PointStamped()  # ← 修正: 用 PointStamped
    msg.header.stamp = rospy.Time.now()
    msg.header.frame_id = "map"
    msg.point.x = x
    msg.point.y = y
    msg.point.z = z
    self.target_pub.publish(msg)
```

### 5.2 电量与通信监控

```python
# mission_manager_node.py
rospy.Subscriber("/mavros/battery", BatteryState, self._on_battery)
rospy.Subscriber("/mavros/state", State, self._on_mavros_state)

def _on_battery(self, msg):
    if msg.percentage > 0 and msg.percentage < 0.2:
        rospy.logwarn("[Mission] LOW BATTERY %.0f%%, triggering RTL", msg.percentage * 100)
        self.fsm.transition("EMERGENCY")

def _on_mavros_state(self, msg):
    self._last_heartbeat = rospy.get_time()
    if not msg.connected:
        self._heartbeat_lost_count += 1
        if self._heartbeat_lost_count > 30:  # 3 seconds at 10Hz
            self.fsm.transition("EMERGENCY")
    else:
        self._heartbeat_lost_count = 0
```

# state_machine.py transition() 中
if event == "EMERGENCY":

elif state == MissionState.EMERGENCY_RTL:

## 八、Mock VLM 测试节点（用于无 API 环境测试）

```python
#!/usr/bin/env python3
# scripts/mission/mock_vlm_node.py — 测试用，模拟 VLM 检测结果
import rospy, json
from std_msgs.msg import String

class MockVLM:
    def __init__(self):
        rospy.init_node("mock_vlm")
        self.call_count = 0
        self.mode = rospy.get_param("~mode", "success")  # success / fail_after_n / timeout
        self.fail_after = rospy.get_param("~fail_after", 5)
        self.target_pos = rospy.get_param("~target_position", [10.0, 5.0, 8.0])

        self.pub = rospy.Publisher("/uav/detection_result", String, queue_size=1)
        rospy.Subscriber("/uav/detection_request", String, self._on_request)
        rospy.loginfo(f"[MockVLM] mode={self.mode}")

    def _on_request(self, msg):
        self.call_count += 1
        rospy.sleep(0.5)  # 模拟 API 延迟

        if self.mode == "success":
            result = {"success": True, "confidence": 0.85,
                      "world_position": self.target_pos, "bbox": [100,100,200,200]}
        elif self.mode == "fail_after_n" and self.call_count > self.fail_after:
            result = {"success": False}
        elif self.mode == "always_fail":
            result = {"success": False}
        else:
            result = {"success": True, "confidence": 0.85,
                      "world_position": self.target_pos, "bbox": [100,100,200,200]}

        self.pub.publish(String(data=json.dumps(result)))
        rospy.loginfo(f"[MockVLM] call #{self.call_count}: {result['success']}")

if __name__ == "__main__":
    MockVLM()
    rospy.spin()
```

**使用方式**：
```bash
# 正常模式（持续返回成功）
rosrun uav_vln_bringup mock_vlm_node.py _mode:=success _target_position:=[10,5,8]

# 第 5 次后失败（测试目标丢失）
rosrun uav_vln_bringup mock_vlm_node.py _mode:=fail_after_n _fail_after:=5

# 始终失败（测试降级模式）
rosrun uav_vln_bringup mock_vlm_node.py _mode:=always_fail
```
