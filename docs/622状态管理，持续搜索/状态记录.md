## 三、当前存在的问题（待修）

### P0：VLM 超时计算有 bug

**位置**：`mission_manager.py` `_trigger_vlm()` 约 505-515 行

**问题**：超时判断用的是 `interval * 0.9`：
- SEARCHING 时：`5.0 * 0.9 = 4.5s` ✅ 勉强够（VLM API 3-8s）
- APPROACHING 时：`2.0 * 0.9 = 1.8s` ❌ 必然超时（VLM API 3-8s，永远比 1.8s 长）

**影响**：APPROACHING 期间每次 VLM 调用都必然计为"超时=没找到"，`miss_count` 虚假增长，无法真正做二次修正。

**修复方向**：加独立 `~vlm_timeout` 参数（默认 10s），不和 interval 绑在一起。

### P1：偏航旋转可能未生效

**位置**：`mission_manager.py` `_search_loop()` + `setpoint_bridge.py` FLYING

**问题**：mission_manager 发 `(sx, sy, sz, yaw=角度)`，bridge 在 FLYING 里转发 yaw。但当 dist < approach_dist（无人机已在目标位置 1m 内）时，bridge 发悬停 setpoint——加了 yaw 但 PX4 不一定在悬停时执行 yaw 旋转。

**影响**：日志里搜"Yaw sweep 0 deg"之后的 goal 一直是 `(0,0,2)`，无法确认无人机是否真的转了。

**修复方向**：需要确认 PX4 在位置悬停时是否响应 yaw setpoint。如果不响应，考虑在搜索时发偏移位置（比如 3m 外）强行使无人机运动。

### P2：VLM 误识别（颜色混淆）

**问题**：命令"蓝色支柱"，VLM 返回红色支柱的 bbox。Qwen-VL 对颜色区分不够敏感。

**影响**：无人机飞向错误目标。

**修复方向**：Prompt 对比实验——测试"框出蓝色支柱"vs"返回蓝色支柱的像素坐标"哪种更准。

### P3：PX4 failsafe 反复触发

```
WARN  [failsafe] Failsafe activated
ERROR [flight_mode_manager] Matching flight task was not able to run, Nav state: 2, Task: 1
```

每次运行都出现，可能跟 OFFBOARD 模式切换或 setpoint 流时序有关，但尚未定位根因。
