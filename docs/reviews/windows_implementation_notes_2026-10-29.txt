Path compatibility contract changes atomically at producer/consumer:
Path.header.stamp = absolute start; pose.header.stamp = absolute sample.
Do not mix a new follower with the old relative-time Path producer.
Sampling is an approximation between published samples; continuous EGO
stream forwarding, actual acceleration tracking and obstacle clearance
are not established by this batch.

The new lifecycle, arbiter, target and bridge cores are offline development
components. Their ROS ownership/feedback wiring must pass Ubuntu gates
before replacing the full flight chain.

Batch 2 changes actual mission/detector/planner/follower wrappers in addition
to pure cores. Managed detection uses one versioned JSON result topic;
registration precedes publication; cancellation and late-result rejection
are tested across real wrapper methods with test-only ROS-shaped stand-ins.
A wall-clock supervisor services API deadlines independently of paused ROS
simulation time. Its real ROS thread scheduling remains untested.
Small refinements keep a live path only when pause=false. A paused vehicle
replans from its new measured state even for a small object refinement.

Current integration limits: the legacy bridge and ROS multi-publisher
topology remain, EGO goal acknowledgement and continuous trajectory stream
forwarding remain, and legacy search goals still need EGO routing. These
are Ubuntu tasks, not completed flight behavior. New core modules are
installed by the proposed catkin rules, but catkin itself was not run.
The replay uses ideal feedback and straight test paths; it does not model
PX4 dynamics, collisions, network threading, real TF or image registration.
