目标与边界

获得Ubuntu后，先完成环境/版本核对和不飞行的ROS集成，再逐步验证PX4、规划、感知和完整任务。所有任务目前均未开始；以下命令、launch/rostest文件名和阈值是后续实施时的验收约定，不代表当前仓库已提供相应文件或测试已经通过。

每个阶段先用人工目标、固定fixture或模拟发布器隔离上游，再接真实组件。所有动态操作限定Gazebo/PX4 SITL；本计划不包含实机飞行，也不包含修改PX4原生位置/姿态控制器。

不确定项先核实再修改：实际PX4/EGO/MAVROS版本、Classic模型子模块、相机安装外参和深度编码、MAVROS速度坐标、实际EGO目标/取消接口。旧环境若无法还原，应选定兼容组合并记录为新的基线，不能把重新下载的main/master认定为旧版本。

验证记录必须保存：业务commit、外部源码commit/子模块commit、ROS包版本、参数文件哈希、测试场景/种子、命令与退出码、rosbag/诊断日志及观察结果。没有实际运行的项目保持未通过。

验证命令：lsb_release -a；python3 --version；rosversion -d；rosversion mavros；gazebo --version；分别在PX4/EGO中执行 git rev-parse HEAD、git describe --tags --always --dirty、git submodule status --recursive；nvidia-smi；图形会话中glxinfo -B。

[ ] U03 核验相机数据、历史TF和MAVROS速度坐标
优先级：P1。依赖：U00/U01、W09；动态数据对照可在U07后补齐。审查关联：12、15、16、26、28。
修改范围：实际模型外参配置、mavros_px4_sitl.launch、相机数据接线、EGO状态输入适配。
任务：组合iris_depth_camera的model/include/link/sensor变换得到真实外参；统一camera_link/optical命名和数据轴方向；核对CameraInfo与深度编码；明确RGB/Depth同步策略和最大时间差；核查实际MAVROS安装源码/消息语义，将EGO所需速度转换为世界系，不能只改frame_id标签。标准MAVROS odom消息本身保持规范语义，转换发生在明确的规划入口。
验证方法：用rostopic info/echo/hz及tf2_echo检查实际话题、编码、尺寸、K、frame和时间；构造yaw=0/90/180/-90度、机体前向速度1m/s的合成输入，逐一核对规划入口世界速度为(1,0)/(0,1)/(-1,0)/(0,-1)；同一已知世界点经不同姿态投影反算；延迟API但仍使用拍摄时刻TF；故意缺历史TF。
通过标准：变换矩阵轴方向/平移与实际模型一致；合成速度数学误差<=1e-6；无噪声已知点重建误差<=0.05米作为初始标定验收值；数据超时/不同步/历史TF缺失不发布有效world目标。运行时数据与合成验证结果一致，否则先解决语义差异再进入后续动态测试。
验证边界：具体噪声、RGB-Depth时间容差及真实定位误差阈值需记录实测分布，不能从无噪声样例直接推广。

任务：目标提交与连续轨迹订阅分离；将每条有效自动重规划和安全停车样条送到执行端；处理EGO重启的traj_id复用；核对当前源码目标z=1硬编码，改为明确导航目标高度；暂停/取消后停止旧目标推进，恢复从实测位置及世界速度重建初态。
关键要求：原始EGO Bspline没有mission/goal ID。必须提供可验证的目标接受确认及返回代次关联（必要时扩展EGO接口），不能只靠“提交之后收到”或时间戳猜测归属。安全停止通道与任务取消优先级需明确。
验证方法：发送人工目标，分别触发普通重规划、障碍重规划、停车、目标变更、取消及EGO重启；对照EGO C++ UniformBspline和Python/执行核心至少100个采样时刻；从/mock odom输入制造暂停后的真实位置与旧理论位置不一致场景；请求z=1.5/2.0/2.2米并检查实际规划终点。
通过标准：样条位置对照误差<=1e-6米且时域/起始时间一致；每次合法重规划ID都到达执行端并明确接受/拒绝；旧goal不被认作新goal；取消后旧目标无执行权；目标高度按约定保留；恢复轨迹起点满足配置位置/速度连续性条件，超出条件转安全状态而非强行追赶。

[ ] U06 接入唯一执行器、正确轨迹模式和真实停止反馈
优先级：P1。依赖：U02/U05、W03/W04/W07/W10。审查关联：04、06、14、20、23、27。
修改范围：开发launch、任务管理/执行器/bridge ROS包装。保留legacy入口，修复版本显式选择新执行链，不让旧节点与新节点同时控制。
任务：mission发送模式/目标/取消意图；唯一executor向bridge发送有效设定值。TRAJECTORY模式不逐点前停；hold一次性锁存位置和yaw；停止/恢复有当前代次确认；节点/数据掉线触发明确策略。
验证方法：rostopic info /uav/goal_pose核对修复模式只有预期执行器发布；检查MAVROS设定值也无其他控制节点竞争；让轨迹参考距离当前点0.3米验证不吞点；注入暂停、取消、旧轨迹、pause=false、新目标和执行器重启；暂用模拟飞控反馈，不飞行。
通过标准：控制输出只有一个所有者；暂停和正常跟踪不交替抢话题；停止命令在一个执行tick内撤销旧轨迹权限并记录反馈；hold锚点不随测量漂移不断移动；取消/安全模式不能被旧消息覆盖。
验证边界：这证明控制命令链，实际制动和位置保持在U07/U10验收。

[ ] U07 SITL中验证基础飞控、抢占、心跳与航向保持
优先级：P1。依赖：U03/U06、W04/W10；只用空白/简单安全场景，不接VLM。
审查关联：05、13、14、21、27。
修改范围：桥接ROS包装与非阻塞状态机、实际反馈/失效处理、必要控制参数；采用新节点或明确模式，原始稳定入口保留作对照。
任务：解锁/模式请求后等待/mavros/state实际确认；起飞失败不误报成功；LAND/取消可靠抢占预发送和爬升；落地确认后再完成；恢复条件和位姿/连接新鲜度可验证。区分安全悬停、紧急降落和电机停止，不用无条件disarm处理全部故障。
验证方法：在yaw=0/90/180/-90度下分别起飞、固定hold、恢复和降落；SITL中注入服务拒绝、连接丢失、位姿过期、起飞高度超时和起飞中取消；记录期望yaw、MAVROS输出yaw及实际yaw；观察60秒设定值流。
初始验收值：20Hz设计输出在60秒窗口内有效消息>=1080，最大间隔<=0.2秒；固定hold稳定后位置误差<=0.3米、最短角yaw误差<=10度并持续10秒。这些是本项目起步验收目标，需记录实际参数/负载；未达标应分析原因，不能直接改松阈值标通过。
通过标准：全部状态以反馈闭环；安全指令不被起飞末尾覆盖；航向无无意归零；失败有有界退出；PX4实际mode与本地状态一致。异常控制测试仅在SITL中执行。

通过标准：规定场景无碰撞、无围栏突破；可行场景按定义完成，无路/越界场景明确停止或失败而非盲飞；只有低速度+位置容差+持续时间满足才到达；搜索路径不再绕过规划。记录最小净空与实际轨迹误差，样本通过不等同所有未知场景安全保证。

[ ] U10 完成分段接近闭环并定位180度现场触发路径
优先级：P1。依赖：U02至U09、W11。审查关联：05至10、18至25、27。
修改范围：BRAKE/SETTLE/WAIT_VLM/WAIT_PLAN/TRACK/HOLD闭环、必要任务参数和诊断日志。

验证方法：对正常任务、API延迟0.1/3/10秒及超过截止时间、BUSY/无目标、目标位置跳变、任务A切B、规划无路、到达后迟到结果各设置固定场景；从多个初始yaw运行；录制任务/检测/规划状态、Bspline、goal_pose、MAVROS设定值、实际pose/odom、TF、clock和实际模式。
