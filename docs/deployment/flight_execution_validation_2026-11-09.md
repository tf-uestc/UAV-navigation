# 2026年11月9日 Iris恢复与第9项飞控执行验收

本次恢复项目的带深度相机 Iris、PX4 v1.14.0 和 MAVROS。恢复初期及动态验收结束后，RGB-D静态检查均为15项通过，分别记录 91 和 87 组精确同步数据。交接时保持场景运行，MAVROS已连接且飞机未解锁。

新增 `flight_verified.launch` 和 `flight_executor.py`。使用与上次一致的EGO消息版本。规划结果在明确授予任务和目标代次后进入唯一执行器，按绝对仿真时间采样并发布 map 系位置及航向。旧目标、旧轨迹和重启前的命令按会话拒绝。执行器按墙钟维护截止时间和发布节拍，使用MAVROS里程计、模式和落地状态确认动作。服务调用独立执行，服务返回与实际反馈分别处理。

ROS输入为 `/uav/flight/command` JSON String，字段包括 `flight_session_id`、递增的 `seq` 与 `command`。先从 `/uav/flight/status` 读取执行器会话。TAKEOFF 可带 `height`。在已进入OFFBOARD悬停且规划就绪后，BEGIN 须携带 `mission_id`、`goal_id`、`gateway_session_id`、`planner_session_id`。HOVER 与 LAND 撤销轨迹权限。停止反馈用 `stop_id` 关联命令，实际位置、速度和航向连续稳定一秒后才确认。验证入口需要 Gazebo 中的项目 Iris、仿真时钟与本地 SITL MAVROS 端点。它只提供第9项控制链，任务状态机接入属于第11项。

首次90°冷启动中，预发送、等待解锁和模式切换占用原先的共用超时，达到超时点时实际高度约1.51 m。调整为准备与爬升各自计时，维持原高度、速度与悬停判定，并加入离线回归。-90°冷启动曾连续30秒读到估计器的0°初值，Gazebo真值为-90°，试验在解锁前中止。准备期间以最新落地位姿更新起飞锚点，在爬升时固定。复验在同一仿真中等到初始航向稳定后再发起飞命令。故障状态下只在收到新鲜落地反馈后上锁。

0°回合使用真实 EGO，收到EGO原生取消确认并在真实PX4反馈中确认飞机停稳。其余三回合使用已知样条验证执行层。四回合均实测起飞、移动、停止、降落与上锁，以及准备阶段降落抢占。0°回合另外实测爬升中降落抢占。MAVROS 回传目标航向与 ROS 发送航向以及实际姿态另行核对。运动里程计的机体系速度经四元数旋转后与 MAVROS 世界系速度对照。

安装空间隔离ROS通过 15 项检查，覆盖拒绝解锁与模式、到达高度超时、规划或飞控反馈失效、重复轨迹及重启前命令。另在真实 PX4 SITL 的执行器输入处注入 4 类异常，包括拒绝解锁、屏蔽到高确认、位姿时间戳过期和连接状态失效。每类异常使用重新启动的仿真，隔离上一轮落地点与状态。原始 PX4 输出用于独立确认退出OFFBOARD或降落并上锁。连接状态由测试转接层注入，验证过程中保留原始 MAVLink 数据供测量。

82项离线回归通过。复现入口为 `tools/deployment/validate_flight_execution.py`，提供 `--mock`（独立master 11315）、`--sitl`、`--real-ego` 和 `--sitl-faults --fault-case`。动态试验用 `UAV_SPAWN_YAW` 指定出生航向，单位为弧度。记录在 `docs/deployment/records/2026-11-09/step9`。航向验收覆盖基础飞行。原先完整分段接近任务的180°触发定位属于第12项。
