## 规划修正

原始箱体场景中，EGO 已接受目标，时间精修后的候选轨迹反复碰到膨胀障碍。增大精修贴合权重后，个别回合仍急停。降低限速、增大地图膨胀后，动态绕行曾成功，近距离静态箱体的初始优化则仍然失败。

分段入口统一设置速度上限 0.32 m/s、加速度上限 0.35 m/s²、膨胀参数 0.349 m、精修贴合权重 20。手动航点每段上限 1.8 m，视觉观察仍为 1.15 m。沿直线遇到已知膨胀障碍时，手动航点任务按当前地图筛选侧向航点。它只使用当前规划会话收到的地图，侧向航点、样条和实际飞行状态继续受原围栏限制。各段分别由 EGO 生成样条，只有实际到达并停稳后才继续。动态急停最多允许一次恢复，需收到本次停止确认、重新取得地图和可行侧路，再以新目标编号提交规划。仍占据的终点交由 EGO 明确拒绝。

EGO 的碰撞检查主要依据已知膨胀栅格，未知区域在任务围栏内可能参与局部规划。侧路筛选同样只使用已知占据。前向 RGB-D 的观测范围取决于航向。用只朝 +X 的深度夹具从空地图启动，EGO 接受了后方 x=-1.4 m 的视野外目标，第一条样条走到 x=-1.353 m。该检查没有启动飞控。净空数据适用于本轮已知 Gazebo 场景。

## 从固定版本恢复

版本、PX4 子模块和 Micro-CDR 提交位于 docs/deployment/records/2026-11-09/final-regression。系统包版本记录的是本次独立构建用到的实际版本。EGO 补丁和恢复流程见 external/ego-planner/README.md。PX4 与 Gazebo 插件用 px4-py38 环境构建。ROS、EGO 和业务安装用系统 Python 3.8.10。视觉节点用系统 OpenCV、NumPy、requests 和云端模型。离线回归使用 offline-py38。

~~~bash
source /opt/ros/noetic/setup.bash
source "$UAV_ROOT/ego-planner/install/setup.bash"
cd "$UAV_ROOT/UAV-navigation/ws"
catkin_make install -j3 -l4 -DPYTHON_EXECUTABLE=/usr/bin/python3
source install/setup.bash
cd ..
roslaunch uav_vln_bringup segment_verified.launch with_detector:=false
~~~

在独立终端按已有部署说明启动项目 PX4 SITL。规划验收使用本机 master 11311，运行 tools/deployment/validate_planning_sitl.py 的 routes 或 dynamic 模式，指定 --out 日志目录。静态障碍使用 tools/deployment/validate_segments.py --obstacle --yaw 0 --out 日志目录。每轮动态及静态箱体使用新启动的仿真。真实检测通过服务器项目的私有 .env 加载凭证，本轮复测限制 4 次请求。
