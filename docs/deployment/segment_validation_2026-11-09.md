首轮真实闭环中，参考位置领先实测约0.65 m，重规划触发连续性保护。分段入口将 EGO 规划速度和加速度均设为0.45，统一管理器、优化器和样条限值。遇到不连续重规划时最多停稳后重试一次，保留连续性保护。执行器先持锁再取反馈检查时间，消除刚到达的反馈被误算为负龄的竞争。

真实视觉初次用“红色三脚支架（标出整个支架）”，返回 map 坐标 [6.714, 0.552, -0.142] m，超过 x=6 m 的围栏。系统拒绝移动，随后降落并解除解锁。将这次任务的提示词收紧为“画面中红色三脚支架中央的竖直红杆，仅框住中央红杆的红色像素，忽略支架其余部分和白色地面”，沿用原深度融合和围栏。两轮真实请求各4次，共 8 次成功请求，均完成三段接近。采样轮的四组RGB与深度时间戳均等于检测结果的采集时间。该提示词的验收范围是当前场景和目标。

补充Gazebo障碍试验中，占据目标被拒绝。随后向障碍后方的无遮挡目标发出规划，自动绕行超时，系统保持悬停并由验收脚本降落。该场景列入 U08 待查，长距离场景及各类规定的重复次数也待验证。未知空间沿用现有 EGO 策略。

在项目SITL、ROS和业务安装环境就绪后，使用 roslaunch uav_vln_bringup segment_verified.launch。启用真实检测时从服务器项目根目录加载 .env，并设置 max_detections:=4 复现本次请求预算。/uav/segment/command 接收 JSON String。START 包含当前 mission_session_id、唯一 mission_id、target 和显式 takeoff 标志。人工目标可用 waypoint。CANCEL 需带当前 mission_id，LAND 用于降落。会话 ID 可从 /uav/segment/status 读取。
