## U05 样条交接、改道和停稳

原清单要求已获当前任务授权的合法轨迹抵达执行端并有接受或拒绝反馈。取消后，旧目标失去执行权。核验按规划器会话、任务、目标 ID 和轨迹 ID 匹配。物理运动是否停止，另用执行器的 HOLD 确认、实际速度与 Gazebo 记录独立判断。

| 证据 | 结果 |
|---|---|
| 原生路径到执行器 | 隔离 EGO 检查 14/14 通过。101 个时刻同 C++ 样条对照，所列最大误差小于 3×10⁻¹⁶。连续重规划 ID 9、10、11 的数据完整保留。请求高度 1.5、2.0、2.2 m 的规划终点为 1.50083、2.00000、2.19978 m。取消后旧样条不可恢复，显式恢复的起点与实测位置相差 0.000172 m；规划器重启会换会话。独立执行器接受首条轨迹、拒绝旧轨迹；速度跳变 0.50 m/s 超过该用例容差 0.15 m/s 时拒绝并停止。 |
| 动态可绕，F03-1-dynamic | 在第一次 TRACK 期间生成箱体。插入后约 0.75 s，EGO 报告预计碰撞；业务样条 (goal=1,traj=2) 带紧停标记，执行器明确接受。2.34 s 时 HOLD 已确认，最近里程计速度 0.099 m/s。重新观察侧方并绕行，依次实际跟踪 (2,3)、(3,5)、(4,7)、(4,8)。最后两条属于同一目标的连续重规划，两条均有执行端接受；全任务到达时距目标 0.137 m、速度 0.032 m/s。 |
| 动态完全封堵，F03-1-blocked | 全宽全高墙生成后约 0.74 s，EGO 报预计碰撞，随后报告紧停后需要新目标。任务收到规划 FAILED 后制动，2.44 s 时 HOLD 已确认，速度 0.065 m/s，2.68 s 宣告 `planner_failed`。实际只有 (1,1) 被跟踪，机体未越过墙体。该轮业务轨迹流没有记录紧停样条，因此也没有相应执行器 ACK。 |
| 权限及剩余可观测性 | 可绕回合直接证明**在授权上下文中**的紧停样条抵达执行器。完全封堵回合直接证明任务撤销和物理刹停。原 F03 记录器采集的是网关输出，无法从它反推同轮两个原生话题抵达网关的精确顺序。源码显示 FAILED 回调撤销当前任务，若旧紧停包其后抵达，网关会静默丢弃；已撤销包、过期 epoch、其他目标都没有执行权。现有证据没有显示仍有效的样条被吞。 |

核对了 `P01-blocked`（上一版 `294933f`），其中 (1,2) 在执行器被明确拒绝为 `wrong_context`。它能说明晚到消息的一种合法处置，不能替代 F03 的逐包身份观察。动态可绕采用中途插入、位置固定的箱，完全封堵采用插入后固定的墙。持续移动障碍不在这些试验内。[可绕事件、实测速率和 ID](scenarios/F03-1-dynamic-events.json) · [封堵事件与刹停](scenarios/F03-1-blocked-events.json) · [执行器负例](../ego-a1/handover.json)
